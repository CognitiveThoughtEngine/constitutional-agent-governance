# constitutional-agent v0.7.0 — Enforced Governance

*Released 2026-07-19.*

Turns the governance thesis from *recorded* into *enforced*: ratification now
authorizes decisions instead of trusting an unverified string, the FRIA model stops
overclaiming EU AI Act Article 27 coverage, and the release figures below are
traceable to the repository.

Verified on Python 3.11, 3.12, and 3.13: **243 test functions / 253 collected, all
passing** across the six library test modules; ruff clean; mypy `--strict` clean;
Bandit clean at MEDIUM+ severity. (Release-tooling tests for the packaging checker
are separate and not counted in this library figure.)

---

## ⚠️ Breaking changes

- **`Constitution.ratify_amendment` is now enforced.** It no longer returns `True`
  unconditionally. Ratification fails closed unless: proposer and ratifier are
  distinct principals (canonicalized); the ratifier is registered; the ratifier's
  authority level covers the **actual affected config paths** (ordinary changes
  need `RATIFIER`; changes touching hard constraints or the authority registry need
  `CONSTITUTIONAL_AUTHORITY`); and the change cannot strand the system with zero
  root authorities. Callers that relied on unconditional ratification, self-ratify,
  or unauthorized hard-constraint/registry edits must now supply an
  `authority_registry`. With **no** registry, the constitution runs in a legacy
  mode: separation of duty is still enforced and ordinary amendments still ratify,
  but any change touching hard constraints or the registry is refused fail-closed.
- **Rejected proposals are terminal.** A rejected ratification sets
  `status = "REJECTED"` (previously left `PENDING`) and can no longer be
  re-ratified or replayed; a fresh attempt requires a new proposal id.

## Added — amendment authority & separation of duties (`authority` module)

- **`AuthorityRegistry`** — a stable `principal_id → AuthorityLevel` map
  (`PROPOSER` < `RATIFIER` < `CONSTITUTIONAL_AUTHORITY`); a registry with zero root
  authorities is rejected at construction.
- **`IdentityVerifier`** — optional deployer-supplied callback binding an asserted
  principal to an external IdP. It may only *add* restriction; it can never bypass
  separation of duty or authority rules.
- **`AmendmentRecord` + pluggable `AmendmentStore`** (`InMemoryAmendmentStore`,
  durable `SqliteAmendmentStore`) — an audit-oriented, monotonically-versioned log of
  every RATIFIED and REJECTED decision, with proposer/ratifier ids and levels at
  decision time, the actual affected paths, before/after constitution hashes, and
  evidence retained scrubbed + by SHA-256 hash. Monotonic `constitution_version` is
  reconstructed across process restarts from a durable store.

## Changed — FRIA model corrected (`fria` module)

- The six built-in categories are relabeled **internal governance-evidence
  categories** (`GovernanceEvidenceCategory`); `FRIACategory` remains a
  backwards-compatible alias.
- Added a separate **Article 27(1) crosswalk** (`generate_article27_crosswalk`,
  `fria_support_package`) over the actual 27(1) elements, each classified by
  evidence source and legal-review status, with an `article_27_applicability`
  determination that defaults to `not_assessed`.

## Explicit limitations (read before deploying)

These are deliberate scope boundaries, stated plainly so nothing is implied that
the code does not do:

1. **FRIA-support ≠ legal FRIA.** `fria_support_package` produces operational
   governance evidence to *support* an EU AI Act Article 27 Fundamental Rights
   Impact Assessment. It is **not** a complete or legally sufficient FRIA. Elements
   requiring deployer context and legal review are marked as such, and whether
   Article 27 applies at all is a deployer/legal determination (`not_assessed` by
   default).
2. **Concurrency is instance-local.** The atomicity and last-authority guarantees
   hold for **one `Constitution` instance in one process**. Cross-process
   ratification requires a durable compare-and-swap in the store — a deployer
   responsibility; the library does not provide distributed locking.
3. **Callback timeout is best-effort.** The raw `IdentityVerifier` fails closed
   when the callback raises or returns any non-`True` value, but it does **not**
   itself impose a timeout and **cannot interrupt a callback that blocks or hangs**.
   Bounding the wait is opt-in via `bounded_verifier(...)`, which is best-effort
   (a worker thread + `future.result(timeout=...)`; the underlying call may still
   run to completion in the background).
4. **Secret redaction is a key-name heuristic, not secret detection.** Before
   persistence, values under a recognized secret-shaped **key name** (`password`,
   `api_key`, `token`, `secret`, `credential`, `authorization`, `bearer`,
   `private`, `signature`, `session`, `cookie`, `otp`, `pin`, `ssn`, or any key
   containing `key`/`auth`) are replaced with `[REDACTED]`. A secret stored under a
   non-matching key, or embedded in free text, is **not** caught — which is why raw
   evidence is additionally retained only by SHA-256 hash, never verbatim. This is
   not a substitute for keeping credentials out of amendment payloads.
5. **Cross-session risk composition is exercised in unit tests, not broadly
   production-hardened.** The `composition` layer (accumulated cross-session
   decision-risk) is covered by unit tests and a durable SQLite store; it has not
   been validated at production scale across deployments. Treat it as a working
   primitive to evaluate, not a battle-tested control.
6. **Competitive framing is a bounded documentation review.** The claim that a
   durable cross-session decision-risk accumulation primitive was *not surfaced in
   the documentation reviewed* refers to a **July 2026 review of public
   documentation** for four named products — not a source-code audit and not a
   claim of global novelty.
7. **Reference thresholds require deployment validation.** Gate thresholds and
   defaults are *reference defaults derived from HRAO-E*; deployment validation is
   the deployer's responsibility.

## Install & verify

```bash
pip install constitutional-agent==0.7.0
python -m constitutional_agent                  # CLI demo — prints system state
```

Artifacts are built deterministically from the tagged release commit on the pinned
Ubuntu/Linux toolchain; the SHA-256 checksums are published with the release and can
be reproduced by rebuilding from the tag.
